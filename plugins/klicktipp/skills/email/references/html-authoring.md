# Import HTML — the mandatory rules

These apply whenever you produce HTML that goes through `replace-email-editor-content-from-html`. They are not
optional: HTML that breaks them is either not imported or imported as a lump that can no longer be
edited.

They do **not** apply to changes through the block tools — nothing is converted there, and what a
block accepts is in [`blocks.md`](blocks.md).

## Contents

## Scaffold

The importer requires valid HTML with `DOCTYPE`, `html`, `body` and an explicit
`<meta charset="UTF-8">`. The `http-equiv` meta may be there as well but does not replace it.

```html
<!DOCTYPE html>
<html xmlns:v="urn:schemas-microsoft-com:vml" xmlns:o="urn:schemas-microsoft-com:office:office" lang="de">
<head>
  <meta charset="UTF-8">
  <meta http-equiv="Content-Type" content="text/html; charset=utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <style>*{box-sizing:border-box}body{margin:0;padding:0}</style>
</head>
<body class="body" style="margin:0;padding:0;background-color:#ffffff">
  <table class="nl-container" width="100%" border="0" cellpadding="0" cellspacing="0" role="presentation" style="background-color:#ffffff">
    <tbody><tr><td align="center"></td></tr></tbody>
  </table>
</body>
</html>
```

Static email HTML only. No JavaScript, no dynamically rendered content, no `.eml`.

## Grid: rows and columns

```html
<table class="row-content stack" align="center" border="0" cellpadding="0" cellspacing="0" role="presentation" style="width:600px;margin:0 auto">
  <tbody><tr>
    <td class="column column-1" width="100%" style="font-weight:400;text-align:left;vertical-align:top;border:0">
```

| Class | Role |
|---|---|
| `nl-container` | the outermost wrapper of the whole email |
| `row` | optional outer row class |
| `row-content stack` | the row itself; `stack` lets columns wrap on mobile |
| `column column-[1-6]` | columns within a row, up to six |
| `pad` | padding on the inner `<td>`, so it stays adjustable in the editor |

- Column widths through `width="50%"`, `"33.3333%"`, `"25%"`.
- **An empty column needs an `empty_block`**, otherwise the grid breaks for drag and drop.
- Prefer 1 or 2 columns. 3 only with very short text; 4–6 only for small simple elements — no long
  labels, no multi-line text. In narrow columns stay at roughly 14–18px.

## Editor block classes

Wrap **every** content element in its own `<table>` with the exact block class, otherwise it is not
editable.

| Class | For |
|---|---|
| `heading_block` | headings `h1`–`h6` |
| `paragraph_block` | running text |
| `image_block` | images and animated GIFs; `src` must be an absolute public HTTPS URL |
| `button_block` | call-to-action buttons; optionally with Outlook VML inside |
| `video_block` | preview image plus play logic; needs a public video/preview URL |
| `list_block` | `<ol>` and `<ul>` |
| `table_block` | data tables |
| `social_block` | social icon rows |
| `menu_block` | navigation; use sparingly |
| `icons_block` | icon collections |
| `divider_block` | horizontal rules; use only where needed |
| `spacer_block` | vertical space |
| `html_block` | custom static HTML/CSS, e.g. a QR code. No JavaScript |
| `empty_block` | mandatory in an empty column |

**How well each survives an import:**

| | |
|---|---|
| reliable | `heading_block`, `paragraph_block`, `image_block`, `button_block`, `list_block`, `spacer_block`, `empty_block` |
| usually, but not as the identical native widget | `table_block`, `social_block`, `icons_block`, `html_block`, static GIPHY/sticker GIFs as `image_block` |
| with care | `video_block`, `divider_block`, `menu_block` |
| never generate or simulate | countdown, vCard — add them in the editor afterwards |

The class alone does not guarantee a native widget: the importer maps existing HTML onto the nearest
structure, it does not build a complex widget configuration. For a bullet-proof template use the
reliable ones only and add the rest in the editor.

**Not to expect as a stable import:** landing-page HTML, HTML generated by JavaScript, private or
internally hosted resources, background images, dividers, menus, unsupported tags with complex
behaviour. Merge tags are **not** interpreted on import — they may be present as static text or
`href` and must be verified in KlickTipp afterwards. Unsupported tags do not necessarily break the
import but can map unpredictably.

## CSS, images, resources

- **Inline CSS** on the elements themselves; `<style>` only for minimal global defaults. No external
  stylesheets.
- Images and other resources must be **publicly reachable**. No private, local, password-protected or
  intranet URLs. The import does **not** upload them into the editor's file manager — it references
  the original URL.
- **No background images** for important content, no complex navigation.
- The importer maps existing structure and styles. It improves no design and adds no missing styles,
  so produce simple robust table structures rather than special layouts; small manual corrections
  afterwards are normal.
- GIPHY and stickers: not as a native add-on, but as an already resolved public HTTPS image URL in an
  `image_block`.

## KlickTipp variables

Use the KlickTipp syntax only. Invent no placeholders.

| Group | Placeholders |
|---|---|
| Person | `%Subscriber:CustomFieldFirstName%`, `…LastName%`, `…Birthday%`, `…Age%` |
| Contact | `%Subscriber:EmailAddress%`, `…CustomFieldPhone%`, `…MobilePhone%`, `…PrivatePhone%`, `…Fax%`, `…Website%` |
| Address | `…Street1%`, `…Street2%`, `…Zip%`, `…City%`, `…State%`, `…Country%` |
| Company | `…CompanyName%`, `…LeadValue%` |
| IDs | `%Subscriber:SubscriberID%`, `…SubscriberKey%`, `…FullContact%` |
| Subscription | `%Subscriber:OptInDate%`, `…SubscriptionStatus%`, `…SubscriptionIP%`, `…SubscriptionDate%`, `…UnsubscriptionDate%`, `…UnsubscriptionIP%`, `…BounceType%` |
| SMS | `%Subscriber:SubscriptionSMS%`, `…SMSSubscriptionStatus%`, `…SMSSubscriptionDate%`, `…SMSUnsubscriptionDate%`, `…SMSBounceType%` |
| System links (`href`) | `%Link:WebBrowser%`, `%Link:SubscriberInfo%`, `%Link:SubscriberUpdate%`, `%Link:ChangeEmailAddress%`, `%User:AffiliateURL%`, `%Link:NoTrack(https://…)%` |

Other custom fields only when the user gives the exact name or ID: `%Subscriber:CustomField[NAME]%`.

## Mandatory footer

Every email ends with a paragraph block carrying the legally required variables — **without them the
later save fails**:

- `%User:Signature%`
- `%Link:SubscriberInfo%` as an `href`
- `%Link:Unsubscribe%` as an `href`

Recommended where fitting: `%Link:SubscriberUpdate%`, `%Link:ChangeEmailAddress%`, and
`%Link:WebBrowser%` in the pre-header or header.

## Valid HTML

The importer parses the code: a structural error produces **no error message** but silently
misnested, swallowed or no longer editable blocks.

**Structure**

- Every element closed, in the order it was opened. No crossed tags, no open `<td>`, `<tr>`,
  `<table>`.
- Void elements without an end tag: `<img>`, `<br>`, `<meta>`, `<hr>`. No `</img>`, no `</br>`.
- Tables fully nested `table > tbody > tr > td`. No content directly in `<table>` or `<tr>`, no text
  outside a `<td>`.
- A block table closes in the same `<td>` it opened in.
- No `<p>` or `<h1>`–`<h6>` nested inside each other. `<li>` only directly in `<ul>`/`<ol>`.
- Exactly one `<html>`, one `<head>`, one `<body>`; nothing between `</head>` and `<body>`.

**Attributes**

- Every value in double quotes, no attribute twice on one element.
- `id` values unique; `block-[n]` numbers consecutive within a column.
- No event attributes (`onclick`), no script content in attributes.

**Characters**

- `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;` — especially in URLs with several query parameters:
  `?utm_source=nl&amp;utm_medium=email`.
- Quotes inside an attribute value as `&quot;` / `&#39;`.
- Umlauts as real UTF-8 characters matching the charset meta, never as mojibake.
- **KlickTipp variables stay as they are** — `%…%` is HTML-neutral and is not escaped.

Before output: count opening and closing tags, above all `table`, `tbody`, `tr`, `td`. Read the whole
document, not only the changed lines — a fragment can look valid and still break the nesting. In
doubt, emit the simpler structure that is certainly valid.

When editing an already invalid template, repair only well-formedness — close a tag, straighten
nesting, escape `&` — and name the repair. That is a forced correction, not a redesign.

## Quality check

- `DOCTYPE`, `<html>`, `<body>`, `<meta charset="UTF-8">` present.
- Valid and static: everything closed, nothing crossed, tables nested `table > tbody > tr > td`, all
  attribute values quoted, `&` in URLs as `&amp;`.
- All images public absolute HTTPS URLs; important styles inline.
- No external stylesheets, no JavaScript, no background images, no complex menus.
- Every content block inside a matching editor block table; empty columns carry an `empty_block`;
  padding-relevant inner cells use `pad`.
- Narrow multi-column sections checked for wrapping — in doubt, 1 or 2 columns.
- Video content uses a real public preview image, or is done as a plain image link.
- No editor-native widget forced through HTML that is better added afterwards.
- The mandatory footer is present.
- **When editing:** outside the requested content changes not one line differs — structure, classes,
  attributes and styles identical to the template.
- If testing through the importer API, send the request body as `text/html`.
