KlickTipp für KI-Agenten

Newsletter schreiben, prüfen und zum Versand vorbereiten, Opt-in-Prozesse lesen — direkt aus Claude oder Codex, über den gehosteten KlickTipp-MCP-Server. Ein Plugin, kein API-Schlüssel, eine Anmeldung. Den Versand selbst bestätigt immer ein Mensch in KlickTipp.

Installieren

Voraussetzung ist ein KlickTipp-Konto. In Claude Code:

claude plugin marketplace add klicktipp/agent-plugins
claude plugin install klicktipp@klicktipp
claude mcp login plugin:klicktipp:klicktipp

In Codex zeigst du die Plugin-Konfiguration auf das Verzeichnis plugins/klicktipp des Repositories. Beide Varianten lesen dieselbe .mcp.json und sprechen denselben Endpunkt: https://mcp.klicktipp.com/mcp.

Die einmalige Anmeldung

Im Paket steckt kein Schlüssel und kein Token. Der Endpunkt liegt hinter OAuth: beim ersten Zugriff öffnet sich ein Browserfenster, du meldest dich mit deinen KlickTipp-Zugangsdaten an und bestätigst den Zugriff. Danach wird das Token gespeichert und selbstständig erneuert — pro Rechner einmal.

Vor der Anmeldung antwortet der Server mit 401. Die Werkzeugliste kann leer bleiben und Aufrufe scheitern mit einem Authentifizierungsfehler. Das ist der erwartete Vorlauf der Anmeldung und kein Defekt — melde dich an, statt die Konfiguration zu ändern.

Der Server eines installierten Plugins ist eine eigene Verbindung mit eigenem, vorangestelltem Namen. claude mcp login klicktipp allein wird abgelehnt; es muss plugin:klicktipp:klicktipp sein. In Claude Code führt /mcp zum selben Ziel.

Der Skill E-Mail-Erstellung

Mit dabei ist ein Skill, der HTML für den HTML-Import des KlickTipp-E-Mail-Editors erzeugt. Dieser Import ist kein allgemeiner HTML-Parser: er mappt vorhandene Struktur auf die Blocktypen, die er kennt. HTML, das nicht darauf hin geschrieben wurde, landet als eine große, unteilbare Textwüste im Editor — importiert, aber nicht mehr bearbeitbar. Der Skill kodiert, welche Struktur der Importer erwartet und welche Elemente sich per HTML überhaupt stabil erzeugen lassen.

Wie es mit deinen Daten umgeht

Alles passiert in dem KlickTipp-Konto, zu dem die Anmeldung gehört, oder in einem Unterkonto, das dieses Konto führen darf. Ein Werkzeug erweitert nie, was ein Unterkonto ohnehin dürfte.

Lesende Werkzeuge laufen ohne Rückfrage. Jedes schreibende ist so gekennzeichnet, dass der Agent vorher fragt.

Kein Werkzeug versendet einen Newsletter. email-newsletter-send prüft Konto, Berechtigung, Inhalt, Empfängerkreis und Absender, nennt den Empfängerschätzwert und gibt eine kurzlebige, einmal verwendbare Bestätigungs-URL zurück. Erst wenn du sie in KlickTipp öffnest und dort bestätigst, ist der Newsletter übergeben — dieser Schritt erreicht echte Empfänger und ist nicht zurückholbar. Ändert sich vorher ein gebundener Wert oder läuft der Link ab, wird die Bestätigung abgelehnt und muss neu vorbereitet werden.

Drei Schreibvorgänge haben kein Zurück, und der Agent soll vorher sagen, was sie kosten:

  • email-newsletter-content-replace wandelt nur HTML. Social-Icons kommen als verlinkte Bilder zurück, Tabellen als einfaches Markup, Video als Vorschaubild, Add-ons als ihre gerenderte Ausgabe; Webfonts, Zeilen-Hintergrundbilder und eigene Head-Styles fallen weg; KlickTipp-Entscheidungen und KI-Blöcke werden unwiederbringlich gelöscht. Was genau es beim jeweiligen Newsletter kostet, steht beim Lesen in replaceWarnings.
  • email-newsletter-content-publish ändert, was echte Empfänger bekommen würden.
  • email-newsletter-draft-delete löscht den Entwurf samt E-Mail, Empfängerbedingungen und System-Tags.

Personenbezug. Die Weiterleitungs-URL eines Abonnenten enthält dessen Kennung, E-Mail-Adresse, Liste, Abonnentenschlüssel und Empfehlungslink — die Antwort von get-subscription-redirect-url ist damit ein personenbezogenes Datum und geht durch den Anbieter des Agenten.

Was dabei verarbeitet wird, regelt die KlickTipp-Datenschutzerklärung; die Nutzung des Dienstes die AGB. Für die Verarbeitung durch den Agenten selbst gilt zusätzlich die Erklärung seines Anbieters.

Wenn es nicht geht

Die Anmeldung in der Claude-Desktop-App scheitert

Das ist derzeit erwartbar und liegt nicht am Plugin: die App registriert sich als OAuth-Client in einer Form, die der KlickTipp-Anmeldedienst ablehnt, der Authorize-Request endet mit HTTP 400. Zwei Wege tragen bis zur Behebung — das Plugin im Terminal installieren und dort anmelden, oder den MCP-Server ohne Plugin von Hand eintragen: 

claude mcp add --scope user --transport http klicktipp https://mcp.klicktipp.com/mcp
claude mcp login klicktipp

Ein von Hand eingetragener Server wird auch von der Desktop-App benutzt, ein Plugin-Server nicht. Laufen beide Wege gleichzeitig, hast du dieselben Werkzeuge doppelt; dann einen der beiden entfernen.

Alle Aufrufe scheitern mit 401

Die Anmeldung ist nicht durchgelaufen. Wiederhole sie, statt die Konfiguration zu ändern.

Ein Werkzeug meldet, das Konto sei nicht erreichbar

Dann gehört das angesprochene Konto nicht zu deiner Anmeldung, oder es ist ein Unterkonto, für das dein Konto die nötige Berechtigung nicht führt.
